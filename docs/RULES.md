# RULES — 작업 규칙 (단일 원본, Single Source of Truth)

> Claude(`CLAUDE.md`)와 Codex(`AGENTS.md`)는 모두 이 문서를 따른다.
> 이 문서와 다른 문서가 충돌하면 **이 문서가 우선**한다. 규칙 변경은 Claude가 하고, `docs/DECISIONS.md`에 기록한다.

---

## 1. 보안·비밀정보 (최우선 — 예외 없음)

### 1-1. 금지
- `.env` 및 `.env.*`(단, `.env.example` 제외) 파일을 **열람·출력·복사·요약·검색하지 않는다.** (`cat`, `type`, `Get-Content`, `grep`, 에디터 열기, 파일 읽기 도구 모두 해당)
- 환경변수 값을 출력하지 않는다. (`env`, `printenv`, `set`, `echo $X`, `print(os.environ)`, `os.environ.get(...)` 결과 출력 금지)
- 키 값을 코드·테스트·주석·문서·커밋 메시지·이슈·PR·로그·채팅 어디에도 쓰지 않는다. 예시값도 실제 키와 같은 형식(`sk-ant-...`)으로 쓰지 않는다 — `<YOUR_KEY>` 같은 자리표시자만 쓴다.
- `git add -f`로 무시 대상 파일을 강제 추가하지 않는다. `--no-verify`로 pre-commit hook을 우회하지 않는다.

### 1-2. 허용되는 유일한 확인 방법
- 키 **존재 여부**만 확인한다: 코드에서 `bool(os.environ.get("NAME"))` → `"설정됨"/"없음"`만 출력.
- 키 누락 에러 메시지에는 **변수명만** 쓴다(값·일부 글자·길이 출력 금지).

### 1-3. 로그·예외·캐시에서의 유출 차단 (구현 의무)
- **law.go.kr API는 인증키(OC)를 URL 쿼리 파라미터로 보낸다.** 따라서 `requests` 예외 메시지(`... for url: ...?OC=...`), 디버그 로그, 응답 객체의 `.url`에 키가 포함된다.
  - 요청 URL·예외 문자열을 로그/파일/콘솔에 남기기 전에 반드시 공용 마스킹 함수(`mask_secrets()`, 위치: `src/precedent_summarizer/common/security.py` — P0에서 구현)를 거친다.
  - raw 캐시에는 **응답 본문만** 저장하고 요청 URL·헤더는 저장하지 않는다.
  - 가능한 경우 `https://`로 호출한다(평문 HTTP 전송 최소화).
- Anthropic SDK 예외·디버그 로그에서도 헤더(`x-api-key`)가 남지 않게 SDK 디버그 로깅을 켜지 않는다.
- 웹 UI 응답·에러 페이지에 환경변수·설정값을 노출하지 않는다.

### 1-4. 자동 방어선
- `scripts/hooks/pre-commit`이 커밋 시 (a) `.env*` 파일 스테이징, (b) 실제 `.env` 값과 일치하는 문자열, (c) 키 형식 패턴을 차단한다. 클론 직후 1회: `git config core.hooksPath scripts/hooks`
- 테스트는 실제 키·실제 네트워크를 쓰지 않는다(모킹/고정 픽스처). 실제 API를 부르는 테스트는 `@pytest.mark.live`로 분리하고 기본 실행에서 제외한다.

### 1-5. 유출 의심 시
작업을 즉시 멈추고 사용자에게 **어떤 변수명이 어디에** 노출됐는지만 알린다(값 재출력 금지). 키 재발급 → `.env` 교체 → 필요 시 git 이력 정리 순으로 처리한다.

## 2. 컨텍스트 연속성 프로토콜 (세션이 끊겨도 이어지게)

### 2-1. 세션 시작 시 읽는 순서 (필수)
1. `docs/RULES.md` (이 문서)
2. `docs/INTENT.md` — 왜/무엇을 만드는가 (잘 안 바뀜)
3. `docs/STATE.md` — 지금 어디까지 왔고 다음은 무엇인가
4. `docs/worklog/` 최신 1개 파일 — 직전 세션의 마지막 상황
5. (해당 시) 배정된 `docs/tasks/TASK-xxx.md`
6. 판단이 필요한 경우에만 `docs/DECISIONS.md`

### 2-2. 세션 종료 시(또는 큰 단계가 끝날 때마다) 갱신 (필수)
- `docs/STATE.md`: 현재 단계·완료·다음 작업·미결정·차단요인을 **덮어써서** 최신화
- `docs/worklog/YYYY-MM-DD.md`: 시각(KST)과 함께 무엇을 했는지 **추가**
- 새로 확정된 결정은 `docs/DECISIONS.md`에 **추가**(기존 항목 수정 금지, 번복은 새 항목으로)
- 커밋까지 마쳐야 종료로 본다(커밋되지 않은 상태는 다음 세션이 볼 수 없다).

### 2-3. 컨텍스트 절약 규칙
- `STATE.md`는 **80줄 이하**. 넘으면 완료 항목을 worklog로 내린다.
- `INTENT.md`는 목적·범위가 바뀔 때만 수정한다.
- worklog는 하루 1파일, 사실만(시각·행위·결과·커밋 해시). 추측·장문 설명 금지.
- 대용량 출력(API 응답 원문, 전체 로그)은 문서에 붙이지 말고 파일 경로만 적는다.

## 3. 분업과 핸드오프

| 담당 | 범위 |
|---|---|
| **Claude** | 아키텍처, 데이터 스키마·모듈 인터페이스, 요약 엔진(프롬프트·출력 스키마·근거 검증기), 품질 평가, 이 규칙 문서 관리, Codex 작업 명세 작성 및 리뷰·병합 |
| **Codex** | 반복·저비중 구현: 판례 수집(페이징·증분·재시도·캐시), 파싱·정제, DB 적재, 단순 CRUD, UI 화면, 단위 테스트 |

- Codex 작업은 반드시 `docs/tasks/TASK-xxx.md` 명세로 시작한다(템플릿: `docs/tasks/_TEMPLATE.md`). 명세에 없는 파일·인터페이스를 바꾸지 않는다.
- Claude가 정의한 스키마·인터페이스(`schemas/`, 엔진 모듈)를 Codex가 변경해야 할 이유가 생기면 구현하지 말고 명세 파일의 "질문" 란에 적고 멈춘다.
- 작업 완료 보고는 명세 파일 하단 "완료 보고" 란에 작성한다.

## 4. 코드 규칙
- Python 3.10+, 패키지 루트 `src/precedent_summarizer/`. `sys.path` 조작 금지.
- **재사용 우선**: 기존 `LawGoKrClient`(원본: OneDrive `Leagal Tech/CODE/python/src/common/law_api.py`)를 이식·확장한다. 같은 기능을 새로 만들지 않는다.
- 설정값은 `.env` → 환경변수 → 코드 기본값 순. 하드코딩 금지.
- 외부 호출에는 타임아웃·재시도·호출 간격(기본 0.1s 이상)을 둔다.
- 경로는 `pathlib` 사용, 인코딩은 UTF-8 명시. 줄바꿈은 LF(`.gitattributes`로 강제).

## 5. 데이터 규칙
- raw 캐시(응답 본문 원문)는 절대 덮어쓰지 않는다. 이미 있으면 재호출하지 않는다.
  - 시간이 지나 내용이 바뀔 수 있는 응답(예: 최근 연도 판례 목록)을 다시 받아야 하면 **날짜가 들어간 새 스냅샷 경로**에 저장한다. 기존 파일은 그대로 둔다(D-013).
  - `save_raw_response()`는 덮어쓰기 옵션이 없다 — 규칙을 코드로 강제.
- API 필드가 비어 있으면 **비어 있는 그대로 기록**한다. 추정·보완 금지(누락은 리포트로 남김).
- 요약의 모든 주장에는 원문 근거 문장(verbatim)을 붙인다. 근거 검증을 통과하지 못한 요약은 저장하지 않고 검토 대기열로 보낸다.
- `data/`는 git에 올리지 않는다(재생성 가능).

## 6. git 규칙
- `main`은 리뷰를 거친 코드만. 작업 브랜치: `codex/TASK-xxx-짧은설명`, `claude/짧은설명`.
- Codex 브랜치는 Claude 리뷰 후 병합한다.
- 커밋 메시지: `type: 요약` (feat, fix, chore, docs, refactor, test).
- 커밋 전 `git status`로 의도하지 않은 파일이 없는지 확인한다.

## 7. 시간 기록
- 모든 시각은 **KST(UTC+09:00)**, 형식 `YYYY-MM-DD HH:MM KST`.
- 단계 시작·종료, Codex 작업 배정·회수 시각을 worklog에 남긴다.
